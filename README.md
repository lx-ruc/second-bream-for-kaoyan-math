# 考研数学第二大脑

一个把「刷过的题」变成「薄弱考点地图」的工具。核心不是错题本，是**纠偏**：用 15 年真题的考法分布，告诉你手上这道题到底该不该做、该做到什么程度。

面向「AI 创造公开赛 · 考研小工具限时挑战」（截稿 2027-01-06）。当前形态：微信小程序 + 可离线打开的原型页。

### 考点树是真题归类，不是大纲

`data/kp.json` 的 92 个考点来自作者三卷「全考点真题索引」，按**真题出场**归类，命名跟着每年真题的实际考法走——**不是按考研大纲编的**。核对结论（`python3 build_audit.py` 可复现）：

| 卷 | 大纲章数 | 考点树章数 | 源索引章数 | 结论 |
|---|---|---|---|---|
| 数学一 | 22 | 20 | 20 | 少「向量代数和空间解析几何」整章 |
| 数学二 | 11 | 11 | 11 | 逐章对齐 |
| 数学三 | 19 | 19 | 19 | 逐章对齐 |

数一那章缺口**在源语料里就有**（`raw/idx1.json` 只有 20 章），不是转换时丢的。另外数一把大纲的「参数估计」「假设检验」两章并成了一章。

后果有两条，都不藏：

- **同一章在三卷下切分不一样**。数一把参数估计拆成矩估计/无偏性/区间估计/假设检验 4 个节点，数三只有一个「参数估计」——所以考频排序里数三那个节点的分数被摊薄，跨卷比同一个概念的名次时要注意这点。
- **多了几组「同一概念两个名字」的节点**（数一「无穷小量的比较」vs 数二「无穷小量」等 14 组），这是打分出现同分并列的一部分原因。`build_audit.py` 把「命名差异」和「真实差异」分开报，混在一起会制造假缺口。

`build_audit.py` 分两层：章级对照、源索引一致性、跨卷结构差异、同义节点是硬事实，可自动判定；「大纲条目有没有独立节点承载」只给证据（题干命中题数、精讲提及篇数），不下结论——关键词自动匹配在这里会大面积误命中（「向量运算」命中「定积分的概念与性质」、「行列式展开」命中「幂级数展开式」），所以那一层靠人工逐条看。

## 怎么跑

### 小程序

用微信开发者工具打开 `考研数学第二大脑/mp`。`appid` 已是正式 AppID（`wx3b8baf398bf449d2`），真机调试可用。真机跑通后把 `setting.urlCheck` 改回 `true`（或先在 mp.weixin.qq.com 后台「开发管理 → 开发设置 → 服务器域名」把 `https://mp-api.app.workbuddy.host` 加入 request 合法域名，二者满足其一即可，目前为开发期临时关闭）。

首次拉代码先装依赖（`node_modules` 不入库）：

```bash
cd 考研数学第二大脑/mp
npm install
```

`miniprogram_npm/` 是构建产物，但**必须入库**：小程序只在 `miniprogram_npm/` 下解析 `require('@tencent-ai/...')` 这类包名，缺了它编译期就 module not found，页面 JS 整份不执行——表现是白屏，连拍照按钮都没有，而且在预览面板里看不到报错。`npm run check` 现在会拦住这种状态。云客户端也改成了懒初始化（`utils/cloud.js` 的 `getCloud()`），SDK 初始化失败只会让识别不可用，不会拖垮整页。

改语料后重新生成数据，改代码后跑校验：

```bash
python3 scripts/build_data.py   # 语料 → data/*.js
npm run verify                  # 静态校验 + 数据完整性 + 三层回归
npm run e2e                     # 开发者工具自动化（见下，需 IDE 环境）
```

`npm run verify` 会检查：JSON 合法性、页面与 tabBar 配置、WXML 标签配对、模板引用的字段是否存在于 `data`、事件绑定是否有对应函数、require 是否断链、WXSS 花括号、WXML 静态类名在 WXSS 里是否有定义；数据完整性（考点树结构、坐标唯一性、题干挂树、考频字段）；题干匹配与 OCR 清洗回归；以及用 mock wx 驱动真实页面 JS 走完录题→判定→存库→诊断的闭环（`scripts/test-flow.js`）。**它不等于能跑**——编译期语义和真机布局只有微信开发者工具能验。

`npm run e2e`（`scripts/test-e2e.js`）分两段：Tool 域体检不需要登录，App 域页面冒烟**需要先扫码登录开发者工具**——touristappid 未登录时 App 域指令全部无响应（IDE 日志特征 errcode 41001），这是环境限制不是代码问题。脚本会自动点掉 IDE 启动时弹的「更新提示」原生弹窗（那个弹窗会堵死全部自动化指令）。

### 拍照识题怎么工作

`拍照 / 相册截图 / 微信图片` 三种来源都走 `wx.chooseMedia` 与 `wx.chooseMessageFile`，先压到 1200px 再送进云服务的视觉模型。

关键设计：**识别结果只用于检索，不用于阅读**。数学公式的识别精度撑不起「把题面读给你看」，但撑得起「在 1224 道真题里找到这是哪一道」。命中之后就换成库里的标准题干，识别时的错字全部丢弃；命中原题后可一键跳到真题详情页看答案与完整解析（答案默认折叠，先自己做）。

找原题的阈值 0.55 是在旧库（475 题、模拟 12% 漏字：自身相似度中位 0.639、p05 0.489，错配 p95 0.415）上定标的。题库扩到 1224 题后回归仍稳定：原文直出命中 100%，模拟漏字 10% 命中 98%、错认考点 0。宁可不认，也不认错题——认错会把错题记到别的考点上，比不识别更糟。

### 刷题价值判定（做题前纠偏）

识别/输入题干后，除了命中原题，还会给出「这道题值不值得刷」的分带判定（`engine.practiceValue`）。判据只有一个：这道题与 1224 道真题的最高的 2-gram 相似度——**值不值得刷由真题库说了算，不出模型观点**。

分带阈值同样用题库自身标定（2026-11-08 全量两两比对）：同考点不同题 5873 对 p95=0.338（≥0.34 即比 95% 的同考点真题对更接近）；跨考点 14365 对 p99=0.226（低于 0.23 与巧合分不开）。

| 带 | 区间 | 判词 |
|---|---|---|
| exam | ≥ 0.55 | 真题级 · 值得精刷（就是这道真题或其轻微变式） |
| worth | 0.34–0.55 | 同考法 · 值得刷（考法在真题射程内） |
| edge | 0.23–0.34 | 考法存疑 · 挑着做（做过对答案即可） |
| skip | < 0.23 | 真题不考 · 建议跳过（近 18 年没这么考过） |

非 skip 带会同时给出最接近的真题坐标（一键看题干+解析）与该考点近六年频次——频次是第二道纠偏：考法贴近但考点近六年 0 次，优先级也要往后放。

### Web 原型

```bash
cd 考研数学第二大脑/v2
python3 ingest.py     # 仅在 raw/ 更新后需要
python3 build.py      # 产出 dist/真题库原型.html（单文件，双击就能用）
```

Web 端也支持**拍照 / 上传截图识题**，且不需要后端：云网关按 `Origin` 放行，`file://` 打开时 `Origin` 是 `null`（放行），`localhost` 也放行，其它来源一律 403。所以双击 HTML 就能直接调视觉模型，密钥写在 `src/ocr-web.js` 里也不怕被别的站点盗用。

两个实测出来的网关约束（踩过，别再试）：

- **只接受 `stream: true`**，非流式一律 `request_invalid_parameter`。因此 `ocr-web.js` 里是自己读 SSE：`res.body.getReader()` + `TextDecoder({stream:true})`，**必须留残留缓冲**——一次 `read` 可能把 `data: {...}` 切成两半，不留缓冲会随机丢字符。
- `glm-4.6v` 在该网关不可用（同样报 `request_invalid_parameter`），视觉可用的是 `glm-5.3-flash`。

Web 端与小程序端共用同一套「识别只做检索」的逻辑和同一个 0.55 阈值，但**清洗与归一化必须两端完全一致**，否则同一张图在两端命中率不同：

- **试卷元信息要清掉**。模型会把「(2022 年 数学一 第 15 题,10 分)」当题面吐出来。同一道题带这条噪声，相似度从 1.000 掉到 0.615；再叠 12% 漏字掉到 0.545，正好被 0.55 挡在门外——认得出却判「没认出」。全量回归：不清噪声命中 73%，清了 98%。
- **上下标要归一**。库内题干是 LaTeX（`^{-1}`）或 Unicode（`⁻¹`），模型可能给 `^-1`。三级对照（含上下标的 1016 题、模拟 12% 漏字）：不归一 p05=0.424 → 只做 Unicode 归一 p05=0.533 → 再把 `^` `_` 一起去掉 p05=0.605。所以 `normStem` 做的是「Unicode 上下标转 ASCII + 抹掉 `^` `_`」。

Web 端冒烟（Playwright，`file://` 直开，与用户实际用法一致）：

```bash
node test-web.js                    # 全链路：上传 → 识别 → 匹配 → 判定 → 存记录
TEST_IMG=/tmp/real_q.png node test-web.js   # 用指定图片
node test-again.js                  # 第 2 步折叠面板：展开 → 改字 → 重新匹配
```

两个脚本都指定了本机已存在的 chromium 可执行文件（插件自带 playwright 的版本号与缓存里的浏览器对不上，不指定会报找不到 `chromium_headless_shell`）。

## 设计上不能动的几条

1. **模型不判断「重不重要」**，重要性只能由真题统计得出，可核对。
2. **题与思路族的关系由用户点选**，不让模型猜。精讲里的「法一/法二」是同一道题的不同解法，**不是**思路族编号，别混。
3. **诊断用中位数不用均值**：每个考点都有几道压轴题永远做不出，均值会拖垮一个已掌握的考点，用户看到就会不信这个数。
4. **熟练度不采自评**，只记四档行为事实（独立做出/提示后做出/看答案才懂/还是不会）。
5. **考频表的 239 个考点与索引的 92 个考点不能自动合并**：名称匹配只有 8%，`泰勒公式` 会被错配到「根据通项公式求极限」。要合并必须人工做映射表。

## 已知限制

- **公式是 Unicode 近似，不是排版**：小程序没有 DOM，跑不了 KaTeX。`xᵐ`、`∫₀ˣ`、`lim_{n→∞}` 这类可用；矩阵、分段函数会失真（qbank 全量解析里矩阵类题尤其明显）。后续换 SVG 图或后端渲染。
- **热度归一化系数是拍的**（n6/8），真实语料做大后要重校。
- **只认印刷体**：手写解题过程识别不可用，产品上也没打算认。用户只需点「卡在哪条思路」，不需要把过程打出来。
- **图片存本地 `USER_DATA_PATH`**，删记录会删图，无人引用的图在进入录题页时清理。
- **小程序端还没有「给提示词让 AI 改」的交互**：Web 端识别面板里有纠错输入框（「认错了？补一句：分母是 x-1 不是 x+1」→ 重识别），小程序端只有「重新识别」按钮，没有这个纠错通道。ima 需求里明确要了，还没补。
