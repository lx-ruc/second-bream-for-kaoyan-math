## 硬约束（用户纠正过，别再犯）
1. 模型不判断「重不重要」，重要性只能由真题统计得出。
2. 题 ↔ 思路族的对应由**用户点选**。精讲解析里的「法一／法二」是同一道题的**不同解法**，不是思路族编号——这条例错两次，用户明确纠正过。
3. 熟练度只记四档行为事实（独立做出 1.0 / 提示后 0.6 / 看答案 0.2 / 还是不会 0），不采自评。
4. 考频表的 239 个考点与真题索引的 92 个考点**名称匹配仅 8%**，`泰勒公式`会错配到「根据通项公式求极限」，不能自动合并，必须人工映射表。→ 已建 `v2/build_kpmap.py`（覆盖 225/239 行、92/92 考点；空间解析几何 15 行有意留空）；评分见 `v2/build_prior.py`，三步链 `build_kpmap → build_prior → build`。
5. 三卷共用一棵超集考点树；画像按五个池聚合（高数三卷分池、线代三卷合并、概率一三合并）。
6. **两套语料不能互相校准**。考频表的一对多映射按 1/n 等额分摊，不许用真题库出场数做权重——那是用 A 语料校正 B 语料，违反「重要性只能由真题统计得出」。等额分摊的不确定性留在界面上说明，不藏起来。
7. **数据分不出高下时不许假装分得出**。8 组考点完全同分（1/n 分摊的必然结果），名次必须并列，不按名字硬拆成 1..92。这与「模型不判断重要性」是同一条约束。

## 云网关约束（2026-11-09 实测，两端通用）
- **只接受 `stream: true`**，非流式一律 `request_invalid_parameter`。必须自己读 SSE。
- **SSE 解析必须留残留缓冲**：一次 `read()` 可能把 `data: {...}` 切成两半，不留缓冲会随机丢字符。
- **按 Origin 放行**：`file://`（Origin 为 `null`）与 `localhost` 放行，任意其它域名 403 →
  所以 **Web 端可以免后端直连**，publishableKey 写在前端也盗不走。
- 视觉可用模型：`glm-5.3-flash`（`glm-4.6v` 在该网关不可用）。

## 题干匹配的硬约束（2026-11-09 标定，两端必须完全一致）
1. **阈值 0.55 不能动**。用 0.55~0.78 六档重标过，0.55 是命中率/误报的最优拐点
   （0.55 命中 90%，0.78 只剩 36%）。
2. **试卷元信息必须清**（年份/卷别/题号/分值）。不清：命中 73%；清：98%。
   带括号的整块必须最先删，否则会留下半边括号拼出新噪声。
3. **上下标必须归一**：Unicode 上下标 → ASCII，再抹掉 `^` `_`。
   p05 提升 0.424 → 0.605（含上下标的 1016 题、模拟 12% 漏字）。小程序库内含 `^` 812 处、`_` 1291 处。
4. **来源（src）不能被匹配结果改写**。拍照认出原题，来源仍是 photo——这是行为事实。
   曾经写成 `IN.orig ? "exam"`，导致来源分布直接失真。
5. 跨考点「错认」明细里，多数是**题库同一道题登记到两个考点**（题干字符完全一致、题号差 1），
   属语料重复，不是算法错，不用管。
