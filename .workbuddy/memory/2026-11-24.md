## ⚠ 发现：云网关鉴权已变（独立于改名，未解决）

**现象**：`https://mp-api.app.workbuddy.host/.cloud/llm/*` 一律 `401 login_required`。
**实测**（curl 直连）：纯文本 `glm-5.3-flash`、模型清单接口同样 401 → 是网关整体策略变化，不是视觉模型单独限制。
**含义**：工作记忆里「Web 端可免后端直连、publishableKey 写前端也盗不走」这条**已失效**，别再按它排障。
**根因**：SDK 官方设计一直是必须登录——Web 走 `signInWithOAuth` + `handleWorkBuddyCallback`，
小程序走 `signInWithWorkBuddyMiniProgram` + `handleWorkBuddyMiniProgramCallback`，并需配置 `workBuddyOAuthClientId`。
我们之前裸调能用，是钻了网关当时不校验登录态的空子。

**小程序端现状**：`utils/cloud.js` 与 `utils/ocr.js` **从未实现任何登录流程**，也没配 `workBuddyOAuthClientId`。
之前能识题完全依赖那个空子。→ 拍照识题在接入登录前**两端都不可用**。
粘贴题干 / 手动选考点 / 真题库 / 考点地图 / 考频 等不依赖云服务的功能不受影响。
小程序端因需登录态，本次未能在本机验证是否同样 401（按同一网关、同一 key 推断大概率是）。

### SDK 错误码事实（排障会用到）
SDK `errorKind()` 把 HTTP 401 归为 `kind: "unauthenticated"`，`code` 是服务端原样的 `login_required`。
**不是** `auth_` 前缀。原 `mapError` 的 `auth_` 规则匹配不到，会落到兜底「识别失败，换张图」——把「要登录」伪装成「图不好」。

### 测试抓到的真 bug（已修）
`onShow` 原来是：`await refreshLogin()`（内部把 `needLogin` 清成 false）→ 再判断 `this.data.needLogin` → 永远 false → 登录后识别续不上。
修法：`refreshLogin` 之前先记 `wasBlocked = needLogin && imgPath`。

### 写 harness 踩的坑（下次别再踩）
1. `utils/img.js` 模块顶层就引用 `wx`，`global.wx` 必须先于任何业务模块 require，否则 `ReferenceError`。
2. 加载 `app.js` 后要手动 `app.onShow({})` 模拟冷启动——否则 `authReady` 是 null，且 SDK 回调计数对不上。
3. 页面 `onShow` 是 async 且页面里不 await，测试要 `await app.authReady` + 一个 tick 再断言。

### 隐私清单
未改。`UserInfo` 指**微信**昵称头像（`wx.getUserProfile` 等）；WorkBuddy 登录是跳官方小程序授权，没调用任何 `wx.getUser*` / `wx.authorize`，不在清单范围。
