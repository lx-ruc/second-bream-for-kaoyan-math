## 考研数学第二大脑 · 产品设计方案 v0.1

**背景**：从 ima 知识库「考研工具挑战」（ima_kb_ZzOdiRvx）读到两篇素材——笔记《考研数学第二大脑》（media_id: note_cls1_cbf865b68d70dab243232f409e710dba_75243772350472017524377117614378）与 B站「AI 创造公开赛·考研小工具限时挑战」活动说明（截稿 2027-01-06，横版视频 ≥1 分钟，标题带【B站AI创造公开赛】）。

**原始设想**：一人一库（容量上限）、逐题记录、按「章节-考点-思路-熟练度」建索引、拍照识别公式并可人工审核纠错、小程序 + Web 双端。

**产出**：`/Users/lixin/WorkBuddy/第二大脑/设计/考研数学第二大脑-设计方案.html`

**核心设计决策（后续迭代沿用，勿轻易推翻）**：
1. 定位是「薄弱点地图」不是错题本——价值单位是考点不是题目；不做自动解题，只做归档 + 归因。
2. 熟练度不靠自评，靠 attempts 行为信号（独立做出 1.0 / 提示后 0.6 / 看答案 0.2 / 仍不会 0）；单题熟练度 = 近 3 次加权均值 × 0.9^(天数/14)；考点熟练度用**中位数**而非均值。
3. 考点树内置（约 320 叶子），AI 只做映射不做自由生成标签，置信度 <0.75 强制确认。
4. 容量 300 题 + 「已掌握归档」出口（熟练度≥85 且 30 天未错），把上限变成维护熟练度的动力。
5. 双端分工：小程序=采集+复习，Web=只读诊断 + 批量补录（八周内不做对等双端）。
6. MVP 明确不承诺手写公式识别，只认印刷体题干；手写卡点用语音/一句话补录。
7. 差异化亮点是「反复卡点」共现统计（跨题统计同一卡点，如 9 题都卡在"不会构造辅助函数"）。

**排期（v0.1）**：W1-2 考点树+识别 pipeline；W3-4 确认页+题库；W5 诊断；W6 复习；W7 Web 只读；W8 补线代/概率+视频投稿。

## v0.2 追加：真题纠偏（2026-11-06）

用户新增需求：以考研数学 15 年真题的考法和思路为准，判断用户提交的题目是否偏离考研考察重点。

**新增设计（已写入同一份 HTML，升级 v0.2）**：
1. **基准**：真题库 real_exams ≈ 1,000 道（2011–2025 × 数一/二/三），每题 6 个标注字段（考点/考法类型/思路族/难度/计算量/年份卷种）→ 聚合为 **exam_profile 命题画像**（考法分布、思路族分布、难度区间、最近考查年份、趋势）。核心原则：**模型只做标注，"重要性"由真题统计算出来**，绝不直接让模型输出"建议跳过"。
2. **考法类型固定枚举 6 种**：概念辨析 / 直接计算 / 证明（存在性·不等式·等式）/ 应用题 / 反例构造 / 跨章节综合。**思路族**：每考点预设 3–5 个标准思路，判定为主族 1.0 / 次族 0.6 / 族外 0.2。
3. **两层判定**：A 层真题最近邻（同考点 + 题干向量，相似度 ≥0.85 直接继承真题标签，可核对、主力）→ B 层模型标注兜底（必须给判定依据句）。
4. **一票否决 + 四维**：超纲（大纲白名单，数一/二/三差异表）直接置 0；四维为考点热度 / 考法匹配 / 思路匹配 / 难度匹配。
5. **贴合度公式**：100 × (0.30 热度 + 0.30 考法 + 0.25 思路 + 0.15 难度)。分档：≥85 真题同源优先做 / 65–84 常规 / 45–64 轻微偏离 / 25–44 考法偏离（看思路不刷同类）/ <25 偏题（跳过）/ 0 超纲。
6. **时间衰减**：近 5 年 ×1.5、6–10 年 ×1.0、11–15 年 ×0.7（2021 年题型结构调整后考法重心变化，不能 15 年等权）。
7. **三个入口**：录入确认页（防垃圾进库）/ 题库体检（清存量）/ 诊断页「练习时间分配：31% 花在偏离题上」（最有说服力的一屏）。
8. **诚实边界**：每条结论必须挂 2–3 道真题证据可展开；用户可否决并进 corrections；出现次数 <3 时只输出"数据不足"；文案只谈性价比，不否定用户资料/老师。
9. **新增数据表**：real_exams / exam_profile / syllabus / question_style / deviation（含 dims、evidence_ids、confidence）。
10. **排期取舍（关键）**：纠偏加入后必须砍——Web 端推迟到赛后（只留只读诊断页录屏）、SM-2 自动排程降级为手动标记、砍同考点变式推荐、砍概率考点树。W1 改为「考点树 + 真题库标注」双基线并行。

**v0.2 待定假设（已被 v0.3 推翻）**：曾建议先只做数一。

## v0.3：数一/数二/数三 全覆盖（2026-11-06）

用户明确要求三卷都做。关键结论：**三卷不是三倍工作量**——真题总量本来就是 1,000 道（15 年 × 3 卷 × 22–23 题），增量成本在标注而非产品结构。

**结构改动（核心，勿推翻）**：
1. **一棵超集考点树，绝不建三棵**。三棵树 = 三套考点 ID = 画像无法复用 = 用户换卷数据搬不过去。超集树约 380 叶子（高数 250 / 线代 60 / 概率 70），三卷共用 ID。
2. **一树 + 三张 syllabus 覆盖层**：`syllabus(kp_id, subject, in_scope)`，约 380×3 行，负责超纲一票否决。
3. **五个画像池（不是三份画像）**——按样本可合并性分，这是关键设计：
   - 高数：数一 / 数二 / 数三 各自分卷（差异最大）
   - 线代：**三卷合并**（大纲几乎一致，合并后样本最足，冷考点才有统计意义）
   - 概率：**数一 + 数三 合并**（数二不考）
4. 大纲矩阵（考点块 × 三卷）：重积分/曲线曲面/场论 仅数一；无穷级数 数一数三（数一含傅里叶）；概率 数一数三；线代三卷全考；高数三卷全考但深度不同。
5. **syllabus 只判"在不在范围"，深度/考法差异交给分卷画像**——两者别混在一张表，这是最容易犯的错。
6. `users.exam_subject` 可中途切换（二战数三转数二常见），切换后触发纠偏重算，提示"将有 N 道题变为超纲"。`deviation.subject_at_judge` 记录判定时科目。
7. 真题标注**分层**：Tier1 精标 2021–2025 三卷 340 题（人工逐题，约 6h）/ Tier2 半标 2016–2020 340 题（预标+10% 抽检，约 1h）/ Tier3 粗标 2011–2015 320 题（预标+只抽高频，约 40min）。
8. 视频脚本新增 38–52s beat：同一条三重积分题，数二看是「超纲跳过」，数一看是「同源 88」——一次交互演示整套白名单在工作，是最强的 demo 点。

**新增风险**：三卷差异只做考/不考会忽略深度差；标注量压垮排期（靠分层缓解）。
